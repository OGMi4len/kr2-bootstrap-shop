# Как открыть и проверить «ХвостКом» на Mac

Степанов Михаил Александрович, ЭФБО-05-25. Версия 2.0, практические занятия №9–11, КР №2. Файлы уже готовы; перепечатывать код из чата не нужно.

## 1. Распакуйте и откройте папку

В Finder дважды нажмите на ZIP. Найдите внутри папку `kr2-bootstrap-shop`: в ней лежат `index.html`, `catalog.html`, `order.html` и папки `css`, `js`, `en`, `vendor`.

В **VS Code** выберите File → Open Folder… и эту папку. В **WebStorm** выберите Open на стартовом экране или File → Open. Открывать нужно всю папку, чтобы редактор видел связанные файлы.

Для запуска зависимостей нет: команды `npm install` и сборка не требуются.

## 2. Откройте сайт

Самый простой способ: дважды нажмите `index.html` в Finder. В WebStorm можно открыть файл в редакторе и выбрать Open in Browser в его контекстном меню. В VS Code для автоматического обновления: Extensions (`⇧⌘X`) → Live Server автора Ritwick Dey → Install → правый щелчок на `index.html` → Open with Live Server.

Сохраняйте правки через `⌘S`. Если открыли файл без Live Server, обновляйте браузер через `⌘R`. Локальный адрес браузера ещё не означает публикацию сайта в интернете.

Ожидаемый результат: главная «ХвостКом» в зелёно-кремовой палитре, с шестью услугами, калькулятором и этапами визита. Кнопка EN открывает английскую версию. Если видите прежний каталог только с тремя услугами, открыта старая папка или старая вкладка.

## 3. Пройдите основной сценарий

1. Откройте «Услуги». Выберите кошку: должно остаться четыре карточки. Для собак доступны все шесть.
2. Нажмите «Выбрать» у купания: откроется окно с ценой и длительностью. Закройте его крестиком или Escape, затем откройте вновь.
3. Перейдите из окна к записи. Купание уже должно быть выбрано; адрес содержит `?service=bath`.
4. Используйте вымышленные данные. Телефон вводится десятью цифрами без `+7`: префикс уже стоит слева.
5. Выберите дату в ближайшие 90 дней и предложенное время. Нажмите «Проверить заявку»: должен появиться итог с пояснением, что ничего не отправлено.
6. Измените поле — старый итог должен скрыться. «Очистить» сбрасывает значения, ошибки и результат.

Также откройте «Подробнее» у каждой услуги: название, цена, время и таблица должны соответствовать карточке. Неизвестный адрес `product.html?service=unknown` должен показать базовую стрижку без ошибки.

## 4. Проверьте новые разделы

- В поиске введите «купание» или «памятка». Выберите результат мышью либо стрелками и Enter; Escape закрывает список. Для случайного набора букв должно появиться сообщение, что ничего не найдено.
- На главной выберите кошку в калькуляторе. Доступны четыре подходящие услуги. Например, три купания дают предварительно 4800 ₽ и 180 минут. Нулевое, дробное или большее 12 число визитов не должно давать рабочую ссылку записи.
- В блоке «Как проходит визит» попробуйте «Старт», «Паузу», «Следующий этап», «Сброс». Это демонстрация процесса.
- В «Сравнении» скрывайте и возвращайте цену и длительность кнопками легенды. Точные значения есть в таблице. Цена и длительность используют две отдельные шкалы, подписанные под графиком.
- В «Памятке» перейдите по оглавлению, скопируйте список и скачайте текст. Если браузер не даёт доступ к буферу, текст выделится: нажмите `⌘C`.
- Переключите EN на странице услуги с параметром в адресе. Должны сохраниться услуга и соответствующая страница. Все девять страниц имеют английские версии.
- Откройте «До и после», «О салоне», «Изменения» и ссылку «Наверх».

Полный список: [CHECKLIST.md](CHECKLIST.md). Отмечайте только собственноручно проверенные пункты.

## 5. Проверьте экран телефона и клавиатуру

В инструментах разработчика браузера изменяйте ширину на 375, 768, 1024 и 1440 CSS px. На маленьком экране сайт не должен прокручиваться целиком вбок. Таблицы и график могут прокручиваться внутри своего блока.

Карточки идут в одну колонку на 375 px, две на 768 px и три на 1024/1440 px. Меню свёрнуто до 1200 px; начиная с 1200 px показывается полная навигация. Поэтому на 1024 px кнопка меню ожидаема.

Пройдите сайт клавишей Tab: должна появляться видимая рамка фокуса, первой доступна ссылка «Перейти к содержимому». Проверьте форму, поиск, легенду графика и кнопки без мыши. Затем проверьте браузер с отключённым интернетом: Bootstrap и данные находятся в проекте.

## 6. Разберитесь в коде

| Файл | Что объяснить на защите |
|---|---|
| `index.html` | Секции главной, Bootstrap-сетка и быстрые переходы |
| `catalog.html` | Карточки, фильтр, метки, окно выбора |
| `product.html` | Таблица, FAQ, данные услуги из адреса |
| `order.html` | `label`, `name`, `required` и классы формы |
| `js/services.js` | Единые данные шести услуг, русские и английские тексты |
| `js/app.js` | Фильтр, URL-параметры, modal и проверка заявки |
| `js/enhancements.js` | Поиск, калькулятор, интерактивные этапы, график и памятка |
| `css/custom.css` | Собственное оформление поверх Bootstrap |

`container` ограничивает ширину, `row` содержит колонки, `col-*` и `row-cols-*` меняют их количество. `g-*` задаёт промежутки. `card`, `btn`, `badge` и `alert` оформляют интерфейс; JS Bundle управляет `navbar`, `modal` и `accordion`.

`preventDefault()` останавливает обычную отправку формы, `checkValidity()` проверяет ограничения, `was-validated` показывает Bootstrap-сообщения. `textContent` выводит введённое как текст. Совместимость услуги берётся из массива `pets`, а время выбирается так, чтобы процедура закончилась до 19:00.

## 7. Проверьте Git перед сохранением

В VS Code откройте Terminal → New Terminal; в WebStorm — вкладку Terminal. Вводите команды по одной, нажимая Enter:

```sh
pwd
git status
git branch --show-current
git remote -v
```

`pwd` показывает папку, `status` — изменения, `branch` — текущую ветку, `remote` — связанный GitHub. Не вводите перед командами символ `$`.

Если получили `not a git repository`, папка из ZIP содержит только исходники. Не создавайте Git в общей папке Documents. Для получения истории существующего проекта можно отдельно клонировать его в новую папку:

```sh
git clone https://github.com/OGMi4len/kr2-bootstrap-shop.git hvostkom-from-github
```

Клон содержит только уже опубликованные изменения. Пока новый PR не объединён, версия 2.0 может находиться только в присланном архиве или локальной ветке `feature/reference-redesign`. Не заменяйте свежие файлы старыми из GitHub. Если вместе с проектом передан новый Git bundle, его можно клонировать отдельно; старые bundle отражают состояние на дату их создания.

Для исходной рабочей папки новая ветка уже подготовлена: `feature/reference-redesign`. Исторические ветки №9 и №10 показывают этапы разработки; PR №1–4 уже объединены, создавать их повторно не нужно.

## 8. Сохраните новую версию и создайте PR

Выполняйте этот шаг после проверки сайта и просмотра своих изменений. Если коммит уже подготовлен, повторный `commit` без новых изменений не нужен.

```sh
git diff --stat
git diff --check
git add .
git commit -m "feat: redesign HvostKom and extend care planning"
git push -u origin feature/reference-redesign
```

`add` подготавливает изменения, `commit` сохраняет их локально, `push` загружает ветку в GitHub. В GitHub Desktop те же действия называются Commit и Publish branch / Push origin. Убедитесь, что выбран ваш аккаунт и репозиторий `OGMi4len/kr2-bootstrap-shop`.

На GitHub: Pull requests → New pull request → **base: main**, **compare: feature/reference-redesign** → Create pull request. В описании перечислите новые страницы и функции, выполненные проверки и оставшиеся ограничения. Откройте Files changed и проверьте состав файлов. После проверки объедините PR через Merge pull request → Confirm merge.

Когда PR объединён, а незакоммиченных правок нет, обновите локальную основную ветку:

```sh
git switch main
git pull --ff-only
git status
```

Ожидается `working tree clean`. Если Git сообщает об ошибке, не выполняйте `reset --hard`, `clean` или force push: сначала разберите сообщение.

В СДО сдаётся ссылка [на репозиторий](https://github.com/OGMi4len/kr2-bootstrap-shop). GitHub Pages необязателен. Статус публикации новой версии проверяйте по фактическому PR, а не по наличию архива.
