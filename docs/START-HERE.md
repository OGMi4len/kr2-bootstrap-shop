# Пошаговая работа на macOS и в VS Code

Автор: Степанов Михаил Александрович, ЭФБО-05-25. Этот документ объясняет готовый проект и позволяет воспроизвести этапы №9–11. Файлы сайта уже созданы: перепечатывать их из чата не требуется.

## 1. Откройте проект

В Finder найдите папку `kr2-bootstrap-shop`. В VS Code выберите File → Open Folder… и эту папку. В левой панели должны быть видны `index.html`, `catalog.html`, `product.html`, `order.html`, папки `css`, `images`, `vendor`. Если видите только архив, сначала распакуйте его.

Откройте Terminal → New Terminal в VS Code. Терминал — место, где вы вводите команды по одной и нажимаете Enter. Перед Git-командами убедитесь, что находитесь внутри проекта:

```sh
pwd
git status
```

`pwd` показывает текущую папку; `git status` показывает ветку и изменения. Не вводите символ `$` перед командами. Не выполняйте `git init` в общей папке Documents или в чужом проекте.

В архиве Git-история передаётся отдельным файлом `git-history.bundle`. Для восстановления истории в новую папку выполните из папки, где лежит bundle:

```sh
git clone git-history.bundle kr2-bootstrap-shop
cd kr2-bootstrap-shop
git switch fix/kr2-final-check
```

Если папка с таким именем уже существует, выберите другое новое имя, например `kr2-bootstrap-shop-history`. Bundle — переносимая копия Git, она не является ссылкой на GitHub. После создания настоящего репозитория поменяйте origin, как описано ниже.

## 2. Запустите сайт

Самый простой вариант: откройте `index.html` в браузере через Finder. Для автоматического обновления можно установить Live Server в VS Code: Extensions (`⇧⌘X`) → найти Live Server, автор Ritwick Dey → Install → правый щелчок на `index.html` → Open with Live Server.

После изменения файла сохраняйте его через `⌘S`. Если открыли HTML как файл, обновляйте браузер через `⌘R`. В адресной строке Live Server будет локальный адрес; это ещё не публикация в интернете.

## 3. Практическая №9 — сетка

Посмотреть именно результат этапа №9 можно безопасно в отдельной папке:

```sh
git worktree add --detach ../hvostkom-stage9 feature/bootstrap-grid-page
```

Откройте `../hvostkom-stage9/index.html` в браузере. Эта версия использует CDN, поэтому для стилей нужен интернет. На ней есть главная, преимущества и популярные услуги. Другие страницы добавляются позже.

Разберите в коде:

- `<!doctype html>` включает современный режим HTML; `lang="ru"` задаёт язык.
- `meta viewport` нужен, чтобы мобильный браузер учитывал реальную ширину экрана.
- `container` ограничивает ширину; `container-fluid` создаёт широкую область.
- `row` содержит колонки, `col-12` занимает всю строку; `col-md-6` занимает половину от 768 px; `col-lg-4` — треть от 992 px.
- Сетка делит строку на 12 частей. `g-4` задаёт промежутки, `my-5` — вертикальные отступы, `h-100` выравнивает высоту карточек.
- Свой `custom.css` идёт после Bootstrap, чтобы небольшие настройки могли его дополнить.

Проверка: на 375 px услуги идут в одну колонку, на 768 px — в две, на 1024 и 1440 px — в три. Не должно быть горизонтального прокручивания всей страницы.

В методичке допускаются два порядка Git для №9. Здесь выбран вариант через Pull Request: начальный `main`, затем ветка с главной. Если создаёте проект заново с нуля, порядок такой:

```sh
git init -b main
git add .gitignore
git commit -m "chore: initialize separate KR2 repository"
git switch -c feature/bootstrap-grid-page
# Создайте главную, CSS, изображения и README, затем проверьте страницу.
git add .
git commit -m "feat: create Bootstrap grid homepage"
```

В готовом проекте эти коммиты уже существуют. Не повторяйте их без изменений.

## 4. Создайте GitHub-репозиторий и первый PR

Откройте GitHub → New repository. Владелец — ваш аккаунт, название — `kr2-bootstrap-shop`, видимость — Public, чтобы преподаватель мог открыть ссылку. Не включайте Add README, .gitignore и license: локально уже есть первый коммит. Нажмите Create repository.

Для этого проекта адрес: `https://github.com/OGMi4len/kr2-bootstrap-shop`. Если репозиторий уже создан, повторно создавать его не нужно.

В локальном готовом проекте сначала проверьте:

```sh
git remote -v
```

Если origin отсутствует:

```sh
git remote add origin https://github.com/OGMi4len/kr2-bootstrap-shop.git
```

Если origin указывает на bundle или другой адрес:

```sh
git remote set-url origin https://github.com/OGMi4len/kr2-bootstrap-shop.git
```

Затем:

```sh
git push -u origin main
git push -u origin feature/bootstrap-grid-page
```

`origin` — имя удалённого репозитория. `push` отправляет коммиты, `-u` связывает локальную ветку с удалённой. Если система попросит вход, используйте GitHub Desktop или предложенную браузерную авторизацию. Обычный пароль аккаунта не заменяет токен для HTTPS Git; не вставляйте секреты в README или чат.

В GitHub: Pull requests → New pull request → **base: main**, **compare: feature/bootstrap-grid-page** → Create pull request. Название: `Create Bootstrap grid homepage`. В описании укажите hero, преимущества, сетку услуг и проверенные ширины. Проверьте Files changed, затем Merge pull request → **Create a merge commit** → Confirm merge. Ветки пока не удаляйте: они нужны для демонстрации.

## 5. Практическая №10 — компоненты

Разберите `catalog.html`, `product.html`, `order.html` и `js/app.js`. HTML каждой страницы полный: общая навигация не создаётся JavaScript, поэтому видна сразу. На каждой странице есть собственный заголовок и активный пункт. На странице отдельной услуги активным остаётся раздел «Услуги».

- `navbar` — шапка; кнопка с `data-bs-toggle="collapse"` открывает меню, а `data-bs-target` указывает на `id` его контейнера.
- `card`, `card-body`, `card-title`, `card-text` — карточка услуги.
- `btn` задаёт кнопку, `btn-primary` и `btn-outline-primary` — её варианты.
- `badge` показывает категорию; `alert` с `role="alert"` — пояснение.
- `modal` открывается по `data-bs-toggle="modal"`. `data-bs-target="#serviceModal"` должен совпадать с `id` окна.
- `form-control`, `form-select`, `input-group`, `form-check` оформляют поля, выбор, телефон с префиксом и согласие. `label for` совпадает с `id` поля.
- `accordion` раскрывает вопросы на странице услуги. Ему, модальному окну и меню нужен JS Bundle.
- `table-responsive` прокручивает только таблицу, если места мало.

`app.js` хранит три услуги, читает `?service=...`, фильтрует карточки и проверяет форму. `preventDefault()` останавливает обычную отправку. `textContent` выводит результат как текст. `novalidate` отключает всплывающие подсказки браузера, а `checkValidity()` проверяет ограничения и включает сообщения Bootstrap через `was-validated`.

Проверка: выберите кошку → две услуги → «Выбрать» у купания → окно показывает цену → «Перейти к записи» → купание уже выбрано. Затем откройте «Подробнее» у каждой услуги и сравните описание, длительность и цену.

В учебном процессе новая ветка создаётся от актуального main после первого PR:

```sh
git switch main
git pull --ff-only
git switch -c feature/bootstrap-components
# Добавьте компоненты, страницы и README. Проверьте их.
git add .
git commit -m "feat: add Bootstrap components pages"
git push -u origin feature/bootstrap-components
```

Если эта ветка уже подготовлена, не создавайте её повторно: просто отправьте её через `git push -u origin feature/bootstrap-components`. В подготовленном проекте она наследует коммит №9; после merge первого PR отличия №10 останутся видны корректно.

Создайте PR **feature/bootstrap-components → main**, название `Add Bootstrap components pages`. В описании перечислите компоненты и шаги проверки. В Files changed должны быть новые страницы и сценарии. После проверки объедините через Create a merge commit. Если выбрать squash/rebase, заранее подготовленные следующие ветки могут показывать повторные изменения — поэтому в этом учебном маршруте используем merge commit.

## 6. Практическая №11 — самостоятельные доработки и проверка

В №11 базовый пример ограничен 2,5 балла из 5. Для большей оценки нужно объяснить расширения, а не только показать другой цвет. В этом проекте добавлены локальный Bootstrap, две страницы, фильтр, перенос выбора и улучшенная форма с расчётом времени. Проверьте их по `CHECKLIST.md` и изучите `REQUIREMENTS.md`.

Сначала были созданы CDN-страницы №9; в итоговой версии файлы Bootstrap находятся внутри `vendor/bootstrap`. Отключите интернет и проверьте открытие сайта, меню, окно выбора и FAQ. Подключение через CDN на итоговых страницах отсутствует.

Для финальных исправлений:

```sh
git switch main
git pull --ff-only
git switch -c fix/kr2-final-check
# Внесите необходимые исправления, проверьте сайт и документацию.
git add .
git commit -m "fix: prepare Bootstrap project for submission"
git push -u origin fix/kr2-final-check
```

В готовом проекте финальная ветка уже создана. После отправки создайте PR **fix/kr2-final-check → main**, название `Prepare Bootstrap project for submission`. Укажите реальные результаты проверок, объедините PR, затем:

```sh
git switch main
git pull --ff-only
git status
git log --graph --oneline --all --decorate -12
```

Ожидается `working tree clean`, актуальный main и видимые коммиты/слияния трёх этапов. Скриншот вкладки Files changed не заменяет проверку сайта в браузере.

## 7. DevTools на macOS

В Chrome или Edge откройте инструменты разработчика через `⌥⌘I`, режим устройств — `⇧⌘M`. Введите последовательно 375, 768, 1024 и 1440 px. В Safari сначала включите функции для веб-разработчиков в Settings → Advanced, затем используйте Develop → Enter Responsive Design Mode.

Проверьте все страницы, карточки, меню, форму, таблицу и окно. Нажимайте Tab: фокус должен быть виден. Escape закрывает модальное окно. В Console не должно быть ошибок JavaScript, в Network — пропавших CSS, JS и изображений. Отключение интернета проверяет локальные зависимости, но не реальную отправку: её здесь нет.

## 8. GitHub Pages и сдача

Публикация необязательна. После merge финального PR: репозиторий → Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save. Дождитесь ссылки, откройте её и повторите проверки меню, услуг и формы. Добавьте фактическую ссылку в README отдельным коммитом/PR.

В СДО отправляется ссылка `https://github.com/OGMi4len/kr2-bootstrap-shop`. Перед отправкой откройте её без входа в аккаунт и убедитесь, что преподавателю видны исходники, README, история и объединённые PR. На защите покажите, какой файл за что отвечает и почему доработки полезны посетителю.
